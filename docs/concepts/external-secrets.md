# External Secrets Operator

## What It Does

External Secrets Operator syncs secrets from an external secret manager into Kubernetes Secrets.

In this lab:

```text
Vault secret
  -> External Secrets Operator
  -> Kubernetes Secret
  -> pod reads Kubernetes Secret
```

Vault is still the source of truth.

## Why Use It

Without ESO:

```text
every app must know how to talk to Vault
```

With ESO:

```text
platform team manages Vault connection
apps keep using normal Kubernetes Secret mounts/env vars
```

This is common in production because it keeps app code simpler.

## Core Objects

`SecretStore`:

```text
how to connect to Vault
which auth method to use
apiVersion external-secrets.io/v1 in our installed operator
```

`ExternalSecret`:

```text
which Vault key/property to sync
which Kubernetes Secret to create
apiVersion external-secrets.io/v1 in our installed operator
```

`Secret`:

```text
normal Kubernetes Secret generated by ESO
```

## Flow In This Repo

```text
Vault has secret/task-api/config
  -> SecretStore vault-task-api uses Vault Kubernetes auth
  -> Vault role task-api trusts ServiceAccount vault-secret-reader
  -> ExternalSecret task-api-config reads username/password
  -> Kubernetes Secret task-api-config is created
  -> pod reads username/password from task-api-config
```

## Direct Vault Vs ESO

Direct Vault:

```text
pod calls Vault API itself
```

ESO:

```text
operator calls Vault
pod reads Kubernetes Secret
```

For many production apps, ESO is easier to adopt first.

## Production Notes

Production should add:

```text
Vault HA and TLS
short refresh intervals only where needed
least-privilege Vault policies
alert when ExternalSecret is not Ready
secret rotation drills
avoid printing secrets in logs
```
